# DocFlow 部署与升级

知华科技（上海如静知华信息科技有限公司）｜https://www.zhuatech.cn/｜商业咨询微信：zhuatech / zhuatech2。

## 本地运行

Docker Compose v2、Python 3。执行 `python3 scripts/init-env.py` 生成权限 0600 的独立 `.env`，然后 `docker compose config --quiet`、`docker compose up -d --build --wait`。前端 http://127.0.0.1:8099/，健康检查 http://127.0.0.1:8099/actuator/health 。账号 admin，密码从 `.env` 的 ADMIN_PASSWORD 读取；密码不提供公共默认值。

默认绑定 127.0.0.1，修改 WEB_PORT 支持多项目共存，指定 `-p docflow-local` 可隔离 Compose 资源。mysql-data 为该 Compose 项目的独立数据卷，不停止或清理其他项目。数据库和后端不暴露主机端口。`.env.example` 是字段说明，不是可直接使用的密码配置。

## 构建

Java 21、Maven 3.9；前端 Node.js ≥24.19.0、npm lock 精确依赖。构建时执行全部测试。Maven 使用 BuildKit 缓存锁、依赖预取、网络重试；前端执行格式检查、ESLint、测试与生产构建。后端保留官方 Java 21 Maven 镜像运行，包含构建工具、体积较大；前后端运行用户非 root。

## 数据与迁移

数据库 zhuatech_docflow，MySQL 8.4。V1/V2 SQL 位于 `backend/src/main/resources/db/migration`；Flyway 版本执行，JPA 只校验。首次建空库初始化基础配置，不填业务资料。升级前备份数据库、保存镜像和配置，对副本先执行迁移及流程验收。已经应用的迁移保持原文件，新改动新增版本。升级失败读取日志并恢复经过验证的备份，不删生产卷重试。

应用源码开发设置 DATABASE_URL、DATABASE_USER、DATABASE_PASSWORD 和 DATABASE_CATALOG；连接目录与库名应一致。示例使用 MariaDB Connector/J 连接 MySQL，仍以 MySQL 8.4 验收。

## 正式部署前

学习版自有代码商用需书面授权。正式部署配置 HTTPS、COOKIE_SECURE=true、反向代理、网络访问控制、外部密钥管理、数据库专用账号、备份与恢复演练、监控告警和审计保留。默认数据库 TLS `sslMode=trust` 不校验 CA，正式环境改为 `verify-full` 并配置证书。单实例内存登录限流不适合分布式防护；未提供多租户、法规合规认证、SSO 或通知服务。

正文、签收信息、导出报告属于业务资料，访问授权和数据保留制度需由部署方管理。勿提交 `.env`、密码、Cookie、原始日志或客户数据。

## 停止与清理

`docker compose down` 停止本项目并保留卷。仅隔离验收库在确认不需要数据后执行 `docker compose down --volumes`；不要对其他项目执行清理或使用全局 prune。
